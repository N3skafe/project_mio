# UI

브라우저나 Electron으로 터미널을 흉내 내지 않는다. Textual 8.2.8 앱이다.

## 배치

위: 앱 이름, 선택 프로젝트, DEMO 또는 LIVE, 연결 상태.

왼쪽: ASCII 캐릭터, 이름, 상태, 짧은 대사. 조용한 모드에서는 대사만 숨긴다. `DEMO · 가상 이벤트`와 상태 줄은 남는다.

오른쪽: Workspace, Review, Lab, History.

아래: 스크롤되는 활동 로그, 명령 입력, 단축키 푸터.

너비 100칸 미만이면 캐릭터를 위로 쌓고 업무 영역을 그 아래에 둔다. 상태 줄이 아트보다 위에 있어서 작은 창에서도 상태가 먼저 보인다.

## 색

- 배경 `#0e1624`
- 본문 `#d5d8de`
- 캐릭터와 검토 강조 `#f0b4b4`
- 작업과 선택과 검색 `#9ec1f0`
- PASS / FAIL / CANCELLED 문자를 함께 보여 준다. 색만으로 결과를 구분하지 않는다.

포커스가 있는 입력, 표, 버튼은 굵은 파란 테두리를 쓴다. 키보드가 우선이고 마우스는 보조다.

## 캐릭터

기본 이름은 미오다. `MAIDOPS_CHARACTER_NAME`으로 바꿀 수 있다.

| 상태 | 대사 |
| --- | --- |
| IDLE | 등록된 작업을 준비해 두었습니다. |
| WORKING | 테스트 출력을 확인하고 있어요. |
| NEEDS_REVIEW | 이 라벨은 확인이 필요합니다. |
| FAILED | 작업이 실패했습니다. 로그를 남겼어요. |
| TRAINING | 확정된 데이터로 학습하고 있습니다. |
| REPORTING | 평가 결과를 확인해 주세요. |
| DISCONNECTED | 백엔드에 연결되지 않았습니다. |

우선순위는 DISCONNECTED, 학습 실행이 `RUNNING`이면 TRAINING, 실행 중 작업이면 WORKING, 초안이면 NEEDS_REVIEW, 기본이 아닌 최신 모델이 있으면 REPORTING, 최근 작업 실패면 FAILED, 그 외 IDLE이다. 라벨 승인만으로는 TRAINING이 되지 않는다. DEMO는 학습 실행이 없으므로 TRAINING으로 들어가지 않는다.

말투는 짧고 정중하다. 실패를 성공처럼 말하지 않고, 라벨 수정 직후 학습이 끝났다고 말하지 않는다. 평가 점수를 친밀도로 바꾸지 않는다.

## 화면

Workspace는 프로젝트, 가상 실행 계획, 작업 표, 경과 시간, 출력을 보여 준다. 테스트 실행, 취소, 실패 사례 이동 버튼이 있다.

Review는 오류 원문, 예측 초안, `RULE_BASED` 또는 `MODEL`, 확정 라벨, 승인, 수정, 보류, 원인과 방법, 변경 이력을 나눠 보여 준다. 모델 초안을 기다리는 동안 라벨은 대기이고 검토 버튼은 꺼진다. 미검토 초안의 확정 라벨은 없음이다.

DEMO Lab은 세션 확정 건수를 보여 주고 `DEMO에서는 학습하지 않습니다`라고 적는다. 학습 시작, 평가 비교, 기본 모델 선택은 비활성화되어 있고 평가 점수는 없다. LIVE Lab은 확정 분포, 분할 미리보기, 조건 이유, 대기·실행 상태를 보여 준다. 조건이 부족하면 학습 버튼을 끄고 이유를 적는다. 학습이 끝나면 고른 모델의 macro F1, 클래스별 점수, 혼동행렬을 규칙 baseline과 함께 보여 준다. 기본 모델은 사용자가 고른다.

History는 세션 작업, 세션 오류, fixture와 세션 해결 기록, 키워드 검색 결과를 보여 준다. 일치하는 기록이 없으면 찾지 못했다고 말한다.

## 갱신

캐릭터를 다시 그릴 때 작업 로그의 `RichLog.clear`를 호출하지 않는다. 다른 작업을 고르거나 출력이 잘려 앞부분이 바뀐 경우에만 그 작업의 로그를 다시 그린다. 상태 갱신은 명령 입력으로 포커스를 옮기지 않는다. Ctrl+L만 명령창으로 포커스를 옮긴다.
