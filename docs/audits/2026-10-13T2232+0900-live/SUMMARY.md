# 격리 LIVE 통합 검증 요약

실행 시각: 2026-10-13 22:32–22:50 KST.  
대상: Compose 프로젝트 `maidops-isolated`, 호스트 `127.0.0.1:55432` / `127.0.0.1:18080`.  
기존 `127.0.0.1:5432` / `8080` 스택, 사용자 DB, 기존 모델 볼륨은 사용하지 않았다.

이 결과는 격리 스택에서 확인한 범위다. 전체 완료나 운영 환경의 안전을 뜻하지 않는다.

## 결론

빈 PostgreSQL 16.15 감사 DB와 V6에서 V8로의 업그레이드는 통과했다. 등록 fixture의 작업, 증분 로그, 검토, 검색, 출력 한도, 타임아웃, 취소, 프로세스 트리 종료, 배치 중복, lease 만료 후 상태 보호를 격리 API에서 확인했다.

공식 trainer가 CPU로 만든 `maidops-mlp-v2`를 재로드 평가로 등록했다. 기본 모델은 학습 완료 때 바뀌지 않았고, 선택 API 뒤에만 바뀌었다. 그 파일 checksum과 새 실패 로그의 `MODEL` 초안이 맞았다. 컨테이너 재시작과 볼륨을 유지한 재생성 뒤에도 파일과 `MODEL` 추론이 남았다.

사람 눈의 TUI 화면과, 감독 예외를 격리 프로세스에 주입하는 항목은 하지 못했다.
