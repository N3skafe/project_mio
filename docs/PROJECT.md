# 프로젝트

MaidOps Lab은 실제 터미널에서 쓰는 개발 조수다. 오리지널 고양이 수인 메이드 "미오"가 작업 상태를 말하고, 테스트 실행과 검토와 기록은 서비스가 처리한다. 캐릭터 채팅 앱이 아니다.

## 현재 단계

PHASE 9까지 구현되어 있다. DEMO TUI, LIVE API, 등록 명령 워커, 규칙 또는 기본 모델 라벨 초안, 사용자 검토, 원인·해결 메모, 키워드 검색, 로컬 해시 유사 검색과 기록 인용 답변, 초안 근거와 라벨 점검 목록, 확정 라벨 학습과 모델 비교, 신뢰 workspace 안의 프로젝트·작업 등록, 실패 로그 가져오기, LIVE 원클릭 기동과 health의 worker/trainer 구분이 포함된다.

로컬 `hashing-char-ngram-v1` 코사인 유사 검색과 기록 인용 답변이 있다. 외부 LLM과 유료 임베딩 API는 없다.

## 하는 일

1. DEMO에서 등록된 가상 시나리오를 재생한다.
2. LIVE에서 `MAIDOPS_WORKSPACE_ROOT` 안의 프로젝트와 `{python}` 작업을 등록하고, 그 작업으로 대기 작업을 만든다.
3. 상태, 경과 시간, PASS / FAIL / CANCELLED 출력을 본다.
4. 이미 나온 실패 로그를 LIVE에서 실행 없이 오류 사례로 가져온다.
5. 실패 로그의 라벨 초안을 승인, 수정, 보류한다.
6. 승인 또는 수정한 사례에 원인과 해결 방법을 남긴다.
7. 이전 해결 기록을 키워드로 찾는다.
8. LIVE에서 확정 라벨이 학습 조건을 만족하면 학습을 시작하고, 끝난 모델을 규칙 baseline과 비교한 뒤 기본 모델을 고른다.
9. 실패 로그와 비슷한 확정 사례·해결 기록을 해시 코사인으로 찾고, 그 기록만 인용한 짧은 답변을 본다.
10. Review에서 초안 근거, 상위 유사 기록 요약, 라벨별 점검 목록을 본다. 점검 목록은 조언이고 확정 라벨이나 학습 점수가 아니다.
11. `scripts/run-live.ps1`로 postgres, backend, worker, trainer를 띄우고, health와 TUI 안내로 무엇이 연결됐는지 확인한다. DEMO는 이 스택을 요구하지 않는다.

## 안 하는 일

- 사용자 입력 문자열을 임의 셸로 실행하지 않는다.
- workspace 밖 경로와 `{python}`이 아닌 실행 파일을 등록하거나 실행하지 않는다.
- 로그 가져오기만으로 성공한 작업을 만들지 않는다.
- 외부 LLM, 유료 임베딩 API, 자동 코드 수정, 임의 셸, 커스텀 학습 라벨 확장을 하지 않는다. 유사 검색은 로컬 해시만 사용한다.
- DEMO에서 실프로젝트 등록 API를 흉내 내지 않는다.

DEMO Lab은 학습하지 않고 점수를 만들지 않는다. 조건이 부족한 LIVE 학습도 점수를 만들지 않고 이유만 보여 준다.

## 원칙

- 단계마다 실행할 수 있는 결과물을 만든다.
- 가상 해결 기록은 `FIXTURE`다. 기본 모델이 없으면 실패 초안은 `RULE_BASED`이고, 기본 모델 파일이 있으면 `MODEL`이다. 파일이나 응답이 없으면 `RULE_BASED`로 닫고 다시 추론하지 않는다. 미검토 초안은 확정이 아니다. 사용자 검토는 `USER`다. 학습 점수는 테스트 분할의 혼동행렬에서만 계산한다.
- 실패를 성공처럼 보여 주지 않는다.
- DEMO 세션 데이터는 프로세스를 종료하면 사라진다. LIVE의 프로젝트 등록, 작업 등록, 실패 로그 가져오기, 검토는 PostgreSQL에 남는다.
- 문서와 화면 문구는 한국어, 코드 식별자는 영어다.
