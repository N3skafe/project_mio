# 보안

## PHASE 2

- 인증이 없습니다. 바인딩과 Compose 포트는 `127.0.0.1`입니다.
- 사용자 입력을 셸로 실행하지 않습니다. `registered_tasks`에는 argv 열이 없습니다.
- 작업 생성은 등록된 `project_id`와 `task_id`만 받습니다.
- 데이터베이스 비밀번호 `maidops`는 Compose와 로컬 기본값이며 운영 비밀이 아닙니다.
- 로그에 요청 본문 전체를 남기지 않습니다.

## 로그 마스킹

워커가 줄을 전송 큐에 넣기 전과, 예외 문구를 SYSTEM 줄로 만들기 전에 `mask_secrets`를 적용한다. 서버와 TUI는 이미 저장된 문자열을 다시 가리지 않는다. 이번 변경은 기존 DB에 남아 있는 과거 로그를 수정하지 않는다.

가리는 형태는 `scheme://user:password@host`, 그 앞에 `jdbc:`가 붙은 문자열, `password`/`token` 같은 대입, `Bearer` 토큰이다. 비밀번호에 공백이나 인코딩되지 않은 `@`가 있으면 놓치거나 일부만 가릴 수 있다. 모든 비밀 형식을 제거하지는 않는다.

## PHASE 4

- 라벨 초안은 프로세스 안의 키워드 규칙이다. 로그를 외부 LLM이나 임베딩 API로 보내지 않는다.
- 규칙 일치 키워드를 정답 확률로 저장하거나 화면에 보여 주지 않는다.
- 승인·수정 전 초안과 보류 사례는 확정 라벨 목록에 넣지 않는다.

## PHASE 5

- 문장 벡터는 프로세스 안의 해시입니다. 사전학습 문장 인코더를 받지 않습니다.
- 모델 파일은 `MAIDOPS_MODEL_DIR` 안의 `mv-`와 숫자 8자리 `.pt`만 읽습니다. 서버는 PyTorch로 그 파일을 실행하지 않고 SHA-256만 확인합니다.
- 학습 완료가 기본 모델을 바꾸지 않습니다. 기본값 변경은 `select-default`뿐입니다.
- 끊긴 학습과 취소된 학습은 다시 큐에 넣지 않습니다.
- 제출된 macro F1이 혼동행렬과 다르면 저장하지 않습니다. softmax를 정답 확률로 저장하지 않습니다.

## 이후 단계에 미리 고정한 경계

- 사용자 문장을 `shell=True`나 셸 문자열로 실행하지 않는다.
- 실행할 작업은 서버에 등록된 task id로만 고른다.
- argv와 작업 디렉터리를 검사하고, 허용된 프로젝트 경로 밖은 거부한다.
- 실행 시간, 출력 크기, 동시 실행 수를 제한한다.
- 비밀처럼 보이는 토큰은 로그에서 가린다.
- 검증되지 않은 모델이나 저장소를 자동 실행하지 않는다.
- 등록 명령은 샌드박스가 아니다. 신뢰하는 프로젝트만 등록한다.
- Windows에서 프로세스 트리는 `taskkill /PID /T /F`로 종료한다. 부모를 바꾸거나 작업 객체 밖으로 빠진 프로세스는 남지 않을 수 있다. 직접 띄운 프로세스가 끝나지 않으면 `CANCELLED`로 확정하지 않는다.
- 취소 요청을 받은 것과 프로세스가 끝난 것을 다른 이벤트로 남긴다.
- 워커가 죽어도 테스트를 무조건 다시 실행하지 않는다.
- 초기 API는 localhost 단일 사용자이며 인증이 없다. 그 상태로 외부에 노출하지 않는다.
